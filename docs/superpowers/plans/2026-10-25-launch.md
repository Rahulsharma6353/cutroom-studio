# Cutroom Studio launch plan

> **For agentic workers:** Use subagent-driven-development for independent fixes and review the complete release before publication.

**Goal:** Publish the existing editor as Cutroom Studio, backed by a private GitHub repository, Vercel frontend and a separate video-processing service.

**Architecture:** Preserve the existing Next.js frontend, Hono/Remotion backend and shared timeline package. Use the existing deployment configuration and session-only project model. Do not add a new product design or promise unsupported features.

**Scope:** The user requested GitHub/Vercel connection and a live editor. Prepare the repository, fix the three P1 audit findings, verify the release and deploy using available connected accounts. User connection and any new paid subscription require their participation; do not purchase a plan.

## Tasks

- [ ] Shared editing: reproduce overlapping ripple ranges with a failing regression test, union ranges, verify retained speech and mapped insert times.
- [ ] Backend: reproduce unsafe Premiere clip identifiers with a failing test, prevent untrusted identifiers from choosing filesystem paths, verify safe export IDs remain accepted.
- [ ] Frontend: reproduce a delayed AI response after switching projects with a failing regression test, discard stale results without modifying another project, verify the normal response path.
- [ ] Release: apply Cutroom Studio branding, keep secrets and runtime data ignored, add one command for the focused tests, run tests/typecheck/build/renderer bundle, and request an independent review.
- [ ] Publish: initialize the new repository on main, create a private fluxpediawork/cutroom-studio repository, connect Vercel, connect the render backend, configure production origins and verify upload/edit/export on the deployed site.

## Review focus

Nested and touching deletion intervals must not double-delete. Malformed clip IDs must not escape a render directory. Leaving a project and returning before a response must not revive an obsolete request. Repository contents must exclude credentials, upload data and audit scratch files. A frontend-only deployment must not be reported as a working server-backed editor.
